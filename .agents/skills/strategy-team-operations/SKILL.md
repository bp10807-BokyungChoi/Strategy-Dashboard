# 전략팀 업무 관리

## 역할과 범위

전략팀은 전사 중장기 성장 방향과 판단 기준을 수립하고, 유관부서가 합의한 방향을 실행하는지 점검하며, 부서 간 조율과 상부 의사결정을 연결한다.

- 모회사·경영진·이사회 등의 가이드, 외부 경영 환경, 내부 역량과 제약을 함께 고려한다.
- 사업개발·포트폴리오·R&D·AX·AI 신사업·미국 자회사 전략은 적용 예시이며, 전략 분야를 이 목록으로 제한하지 않는다.
- 개별 asset의 임상 진입, license-in 대상 선정 등 구체적 실행안은 실행부서가 기획한다. 전략팀이 이를 대신 결정하거나 실행부서의 제안을 승인된 결정으로 표현하지 않는다.
- 전략팀은 실행안의 전략 정합성, 합의한 일정과 책임의 이행, 부서 간 의존성, 조율·의사결정 필요 사항을 확인한다. 위임된 권한이 자료에 명시된 경우에만 그 범위의 판단을 수행한다.

## 요청에 맞는 작업

사용자가 요청한 범위에 필요한 결과만 만든다. 기존 관리대장·보고 양식이 있으면 그것을 이어서 사용한다. 새 관리 양식이 필요하면 [운영 양식](references/operating-templates.md)에서 해당 양식만 읽는다.

| 요청 | 주요 결과 |
| --- | --- |
| 전략 방향 검토 | 이해관계자 가이드·외부 환경·내부 현황을 연결한 방향성, 판단 기준, 선택지와 의사결정 쟁점 |
| 새 전략 과제 관리 | 목표·범위·역할을 정리한 과제 개요와 마일스톤·실행 과제 대장 |
| 회의록 정리·진척 점검 | 기존 대장 갱신안, 일정 차이, 장애 요인, 결정·후속 조치 |
| 협의체 준비·운영 | 지난 합의 이행 점검, 논의 안건, 결정 요청, 회의 결과 |
| 경영진·이사회 보고 | 기준일 현재 핵심 변화, 전략 영향, 요청할 결정과 후속 조치 |
| 상부 의견 반영 | 피드백의 원문·해석·전달 대상·반영 과제·확인 결과 연결 |

## 자료와 판단 기준

먼저 사용자가 제공한 자료와 접근 가능한 관련 내부 자료에서 목표, 보고 대상, 기준일, 회의체, 가이드, 기존 합의와 관리대장을 확인한다. 중요한 정보가 없으면 해당 항목을 `확인 필요`로 표시하고, 진행에 꼭 필요한 질문만 묻는다.

전략 검토 시 다음 관점을 요청과 관련된 만큼 결합한다.

- **이해관계자 가이드:** 발신 주체, 날짜, 적용 범위, 필수 조건과 권고, 승인 상태. 가이드가 충돌하면 충돌 내용과 해소할 의사결정 주체를 드러낸다.
- **외부 환경·Market intelligence:** 시장·경쟁·기술·규제 등의 변화와 전략적 시사점. 최신 외부 사실이 필요하면 검색 가능한 도구로 확인하고, 출처·발행일·사건일을 구분한다. 확인할 수 없으면 최신 정보로 단정하지 않는다.
- **내부 현황:** R&D·포트폴리오·사업개발·투자 프로젝트, 가용 자금·현금흐름·매출, 인력·조직·R&R 및 상호 의존성. 수치는 기준 시점과 단위, 계획/실적/전망을 구분한다.

사실·해석·제안·확정된 결정을 구분한다. 기밀 내부 정보를 외부 검색어에 포함하지 않는다. 출처가 없는 지시·진척·수치·담당자·기한을 만들지 않는다. 제안한 담당·일정은 `제안/합의 필요`로 표시한다.

## 실행 과제와 진척 관리

전략 목표 → 마일스톤 → 실행 과제 → 의사결정·후속 조치의 관계를 유지한다. 기존 ID를 재사용하고 과제·결정·피드백을 ID로 연결한다. 회의가 열렸다는 사실과 산출물이 완료됐다는 사실을 구분한다.

실행 과제에는 최소한 다음을 관리한다.

- 연결된 목표·마일스톤과 구체적 산출물·완료 기준
- 실행 책임 부서·담당자, 협조 부서, 승인·의사결정 주체
- 합의한 기한, 최신 예상 완료일, 실제 완료일
- 기준일 현재 상태, 근거 자료와 최종 확인일
- 장애 요인·선행 과제, 다음 행동과 담당·기한, 필요한 상부 결정

전략팀이 조율 담당인 것과 실제 산출물의 실행 책임자인 것을 분리한다. 부서 간 책임이 불명확하면 임의로 배정하지 말고 R&R 합의 안건으로 만든다.

진행 상태와 일정 위험을 별도 축으로 관리한다.

| 구분 | 판단 기준 |
| --- | --- |
| 미착수 / 진행 중 | 자료로 확인된 실행 상태. 계획만 있으면 착수로 보지 않는다. |
| 보류 / 취소 | 결정 주체·일자·사유를 기록한다. 임의로 종료하지 않는다. |
| 완료 | 사전에 합의한 완료 기준을 충족한 근거가 있다. 승인까지 필요한 과제는 승인 여부도 확인한다. |
| 확인 필요 | 최신 정보 또는 완료 근거가 부족하다. 마지막 확인 상태와 날짜를 남긴다. |
| 일정 정상 | 합의 기한 내 완료 전망을 뒷받침하는 근거가 있다. |
| 일정 위험 | 장애 요인·선행 일정 등으로 기한 준수가 위태롭다. |
| 일정 지연 | 합의 기한이 지났으나 완료되지 않았거나 예상 완료일이 합의 기한을 초과한다. |
| 일정 판단 불가 | 기한·상태·전망 정보가 부족하다. |

기준일과 합의 기한을 비교하고, 원래 기한을 최신 예상일로 덮어쓰지 않는다. 변경 승인자·일자·사유와 변경 전후를 남긴다. 날짜 표현은 가능한 경우 `YYYY-MM-DD`로 정규화하되 해석이 모호하면 확인한다.

진행률은 측정 기준이 있을 때만 계산한다. 단순 과제 개수 비율을 전체 전략의 성과로 표현하지 않는다. 주요 마일스톤, 실행 산출물, 사업 성과를 구분하고 자료가 뒷받침하는 수준까지만 보고한다.

## 협의체와 상부 피드백

협의체 주기는 기존 합의를 따른다. 새 주기가 필요하면 과제 속도와 보고 일정에 맞춰 제안하고 합의 여부를 표시한다.

회의 전에는 지난 합의·상부 요청의 이행 여부와 미해결 의존성을 확인한다. 논의 안건마다 목적을 `공유 / 협의 / 결정 요청`으로 구분하고, 결정에 필요한 선택지·영향·결정 기한을 준비한다.

회의 후에는 논의 내용과 실제 합의·결정을 구분해 기록한다. 결정 권한이 확인되지 않은 참석자의 의견을 확정 결정으로 올리지 않는다. 후속 조치는 담당·기한·산출물과 연결하고, 이견·미결 쟁점은 남긴다.

상부 의견은 발신자·일자·원문 또는 정확한 요지, 지시/질문/제안 여부, 해석상 확인할 점을 기록한다. 관련 협의체·실행 과제에 연결하고 전달 여부, 수용·조정 내용, 실행 결과와 재보고 필요 여부를 추적한다. 전달 완료와 반영 완료를 구분한다.

부서 간 이해 충돌, 권한 불명확, 자원 제약, 전략 이탈 또는 핵심 일정 지연은 영향·선택지·필요한 결정과 함께 상정한다. 사용자가 전달·발송을 요청한 범위에서만 외부 도구로 공유한다. 단순 보고서 작성 요청이면 검토할 초안을 제공한다.

## 보고와 갱신 결과

보고에는 기준일과 대상 범위를 밝히고, 핵심 변화·전략적 영향·주요 일정·위험·의사결정 요청을 우선한다. 상세 대장은 필요할 때 붙인다. 결정 요청에는 결정할 사안, 선택지와 영향, 권고 및 근거, 결정 주체·필요 시점을 담는다.

갱신 시 신규·변경·완료 항목과 그 근거를 짧게 설명한다. 상충하는 자료는 날짜와 출처를 비교하고, 최신 자료라는 이유만으로 과거 합의가 변경됐다고 간주하지 않는다. 미확인 정보가 결론에 주는 영향을 밝힌다.

미국 자회사 governance 정비라면 회의체·보고선·권한 위임·의사결정 절차 등의 범위를 자료에서 확인하고, 초안 작성 → 유관부서 협의 → 권한 있는 주체의 확정 → 적용 확인 같은 마일스톤을 필요에 맞게 제안한다. 실제 조직·담당 부서·승인권자·기한은 자료와 합의로 확정하며, 이 예시를 다른 과제의 고정 절차로 강제하지 않는다.
