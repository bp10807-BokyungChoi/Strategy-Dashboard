# 전략팀 업무 대시보드 구현 계획

## 구현 근거와 범위

사용자가 설명한 전략팀 역할과 2026-11-25의 실행 요청을 기준으로 한다. 자동 전사에는 오류가 있으므로 문장 전체를 확정 지시로 취급하지 않는다. 원본 녹음과 전사 전문은 저장소에 포함하지 않는다.

- 사용자 확인: 전략팀은 방향·판단 기준·실행 점검·조율을 담당하고 구체적 실행안은 실행부서가 기획한다.
- 사용자 확인: 통합 현황을 중심으로 상부 의견 추적 대장, 협의체 및 경영진 보고 초안이 필요하다.
- 전사 04:49~05:30, 07:25~08:35: 전체 일정·마일스톤, 직접 입력, 전체 뷰, 상태 색상에 관한 설명이 앞선 요구와 일치한다.
- 전사 09:58~10:24: 작은 단위로 구현·검증하고 커밋하는 접근을 적용한다.
- 전사 10:43 이후: 문서에서 액션 아이템을 추출하는 기능은 후속 단계로 분리한다. 미확인 발언·이름·연도는 업무 데이터로 넣지 않는다.

## 첫 구현

1. 전체 현황: 기준일·검색·과제·상태 필터, 일정 위험, 다음 행동·결정 요청, 전체 일정.
2. 실행 과제: 전략 영역·과제명·실행 부서/담당·전략팀 조율·기한·전망·상태·완료 기준·근거·후속 행동·쟁점·출처의 입력과 수정.
3. 상부 의견: 실행 과제 연결, 발신·유형·전달·반영을 분리하여 기록. 반영 확인 시 완료 기준과 근거 확인.
4. 협의체·보고: 현재 데이터와 기준일을 이용해 안건 및 상부 보고용 텍스트 초안 생성·저장. 외부 발송 없음.
5. 보관: 브라우저 내 로컬 저장, JSON 백업·검증 후 가져오기. 빈 업무 공간과 가상 예시 체험을 분리한다.

완료 비율을 전략 성과로 표시하지 않는다. 일정 위험은 상태와 별도로 계산한다. 기한이 없거나 확인되지 않은 상태는 판단 불가로 남기며, 보류·취소를 완료로 계산하지 않는다. 완료 및 반영 확인에는 개별 완료 기준·근거가 필요하다. 합의 기한 변경에는 사유·확정 주체를 기록하고 이력을 보존한다.

## 후속 단계

실제 자료와 출력 화면을 검토한 뒤 엑셀 양식·가져오기, 회의록 액션 추출 후보의 검토·반영, 공동 사용·연결·주기 실행을 구체화한다. 첫 구현에 문서 의미 분석이나 AI 자동 추출 기능이 있다고 표시하지 않는다.

## 검증과 제한

일정 경계·완료 조건·과제 연결·가져오기·보고 일치성은 Node 테스트로 검사한다. 브라우저에서 가상 예시와 실제 빈 공간 전환, 과제 및 피드백 저장, 새로고침 복원, 백업 내보내기, 모바일 배치를 확인한다.

데이터는 사용하는 브라우저와 주소에 저장된다. 브라우저 데이터 삭제·기기 이동에 대비해 JSON 백업을 제공한다. 공동 편집이나 서버 저장은 이 단계에 포함되지 않는다. 예시의 담당·일정·진척은 모두 가상이며 실제 회사 현황을 뜻하지 않는다.

## 첫 구현 검증 결과 (2026-11-25)

- `node --test strategy-dashboard/core.test.js`: 10개 통과. 일정 경계, 확인 불가·위험, 완료 조건, 날짜 순서, 피드백 전달·반영 구분, 백업 왕복·연결 검증, 기한 이력, 기준일 이후 완료, 보고 반영을 확인했다.
- JavaScript 구문 검사와 `git diff --check`를 수행했다.
- 브라우저에서 빈 공간과 가상 예시의 분리, 신규 과제 등록, 기한 변경 사유·확정 주체의 필수 입력, 근거 없는 반영 확인 차단, 수정 결과의 보고 초안 반영을 확인했다.
- 별도의 검증 주소에서 과제 저장 후 새로고침 복원, JSON 백업 다운로드, 빈 백업 가져오기, 다운로드한 백업으로 복원하는 흐름을 확인했다. 검증 공간은 빈 상태로 되돌렸다.
- 최종 화면의 한글·일정·표 배치를 데스크톱 브라우저에서 시각 확인했다. 반응형 CSS를 포함했으나 별도 모바일 기기와 인쇄 결과는 검증하지 않았다.
- 실제 업무 공간에는 회사의 담당·기한·진척을 임의로 입력하지 않았다. 공개 배포, GitHub 푸시, 기존 PR 수정은 수행하지 않았다.

시작 방법: `strategy-dashboard/index.html`을 브라우저에서 열거나 저장소의 정적 서버 루트에 접속한다. 상단의 ‘가상 예시 체험’으로 흐름을 확인하고 ‘내 업무로 돌아가기’에서 실제 과제를 등록한다. 실제 업무 자료가 제공되면 출처를 확인해 입력·가져오기 범위를 정한다.
